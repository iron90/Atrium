# Atrium 开发计划

这份计划把 Atrium 的产品边界、已完成能力和后续批次固定在仓库中，作为
后续开发 Agent 的工作入口。实现顺序以“先让看板中的事实可信，再形成执行
闭环，最后扩展跨项目管理能力”为原则。

## 不变的设计边界

- Atrium 是本地项目看板，负责展示事实、调用项目入口和记录本地结果。
- Git 仍然负责版本管理和远程备份；Atrium 不改写 Git 历史。
- 平台、渠道、构建配置和可清理目录只来自 `.atrium/manifest.toml` 的结构化声明。
- 不解析任意 Markdown 来生成项目事实，不依赖 AI 扫描项目。
- 项目负责业务逻辑、平台差异、渠道差异和原生构建流程；Atrium 不替换这些流程。
- 正式的 Run / Check / Build 配置与仓库中自动发现的命令保持独立。
- 不引入通用 Stage，不管理项目开发 Agent，也不在一期接入网站、支付或发布服务。
- 不通过 Atrium 复制模板或创建项目脚手架；项目由其常规开发工具创建，Atrium 只负责协议接入。
- UI 支持中英双语、主题和布局切换；所有新增事实都要保留来源证据。
- 任何跨平台行为都必须有 Windows、macOS、Linux 的通用路径，或返回明确能力错误。

## 基线核对（2026-09-15）

已具备：

- 工作区一级项目扫描和项目列表。
- Git 分支、工作区未提交变更数量、上游领先/落后提交数量、远程地址和近期提交读取。
- 图标规范 `icon.v1`、旧项目图标兼容显示和引导报告。
- `platforms`、`channels`、`build_profiles` 的确定性 manifest 解析。
- 平台与渠道组合下的 Run / Check / Build 命令绑定。
- 仓库原生命令确定性发现，默认隐藏并在用户确认后展示。
- 项目图标、磁盘统计和协议声明的清理目录入口。
- 项目切换先更新选中态，详情异步加载。
- 中英文、三套主题和两种布局。
- Tauri 2 + React + TypeScript + Rust 的跨平台分层。

第一批已完成（2026-09-15）：

1. 能力级协议状态和清晰的协议版本信息。
2. 单一接入引导中对缺失能力、无效字段和版本的统一说明。
3. 语言、主题、布局和工作区设置的本地持久化。
4. 单项目刷新、工作区自动更新和刷新状态反馈。

第一批仍明确不包含：SQLite 运行记录、多工作区、Git 变更范围汇总，
以及网站/支付/发布服务连接。

## 批次一：协议与信息可信度

状态：已实现。协议 DTO、确定性能力评估、统一引导入口、偏好持久化、原生轻量自动
刷新和单项目刷新已接入当前可运行版本。

### A. 能力级协议状态

将协议总状态拆成可独立校验的能力：

- 基础身份与图标。
- 平台与渠道上下文。
- Run / Check / Build 配置。
- 清理目录声明。

每项显示 `已配置`、`部分配置`、`未声明` 或 `无效`，并携带 manifest 证据和问题原因。
未声明的可选能力不作为项目异常；依赖某项能力的操作根据该能力单独启用或禁用。

验收：

- 协议卡片位于所有依赖协议的详情区块之前。
- 平台和渠道不再使用图标状态冒充完整配置状态。
- 缺失或无效原因可以直接指导项目开发 Agent 修改 manifest。

### B. 协议版本与统一接入引导

- 在协议状态中显示 manifest schema 版本。
- 对缺失、无效和不支持版本使用确定性的错误信息。
- 保留一个“生成配置引导文件”按钮，一次生成配置和图标引导。
- 引导内容覆盖当前实际缺失能力，并生成可复制给项目开发 Agent 的固定提示词。
- 生成过程不读取引导 Markdown 作为项目事实，也不覆盖已有有效配置。

验收：

- manifest schema 不是 1 时不会显示为可执行的有效配置。
- 引导报告和 UI 的缺失能力保持一致。

### C. 设置持久化

第一阶段持久化以下本地偏好：

- 语言、主题、布局。
- 当前工作区路径。

偏好写入 Atrium 自己的本地存储，不写入项目仓库。后续 SQLite 持久化运行记录和
多工作区时，保留迁移入口。

验收：

- 重启 Atrium 后偏好仍然存在。
- 浏览器预览和原生 Tauri 会话都能安全处理存储不可用的情况。

### D. 自动更新与单项目刷新

- 提供当前项目的单项目刷新按钮。
- 以跨平台确定性的 10 秒轻量检查周期刷新工作区；只有事实发生变化时才更新列表。
- 保留当前选中项目，不因自动刷新跳回第一项。
- 配置、Git 状态、命令来源等变化会触发详情重新读取。
- 显示刷新中、最近刷新时间和刷新失败状态。
- 项目切换的高亮始终先于详情加载；过期异步结果不能覆盖当前项目。
- 磁盘统计仍然只在详情检查中异步读取。

验收：

- 修改 manifest 或 Git 工作区后，下一次轻量刷新能反映变化。
- 自动刷新不递归计算所有项目磁盘占用，也不阻塞列表交互。

本批次历史验证结果：Rust 单元测试 14 项、前端测试 5 项、TypeScript 类型检查、ESLint、
Rust 格式检查和 Tauri macOS 应用构建均通过。当前质量门禁还会持续复验这些边界。

## 批次二：执行与结果闭环

状态：已实现（2026-09-15）。本批使用应用数据目录中的确定性 JSON 存储运行记录；
SQLite 仍作为后续多工作区和更大规模历史数据的迁移方向。

### E. 执行记录与日志

- 已持久化运行记录、实时 stdout/stderr、停止、退出码、耗时和最终状态；每个输出流最多
  持久化 256 KiB，超长单行最多保留 16 KiB，并继续排空管道后给出截断标记。
- 已记录项目路径、平台、渠道、配置、实际命令、Git 分支/提交和工作区状态。
- 当前不提供独立运行记录页面；运行记录继续作为项目命令执行的本地结果保存，后续在
  项目详情中按项目重新设计查看、日志和重执行入口。
- 已设置本地历史最多保留 100 条；后续再增加可配置的数量/空间策略。

验收：运行完成后即写入应用数据目录 `run-history.json`，应用重启后仍可读取；日志
打开时写入应用数据目录下的 `logs/<run-id>.log`，不修改项目仓库。

### F. 构建产物入口

- 已由项目协议按构建配置声明产物目录或文件。
- 已在详情页显示声明路径、文件/目录类型、存在状态、大小、文件数和更新时间。
- 已支持打开存在的声明产物；不推断框架默认输出目录。
- “本次变化”需要构建前后快照或 Git/产物历史，列入后续批次，当前不伪造变化结论。

验收：未声明产物时不显示框架默认目录；声明路径不存在时只显示“尚未生成”，不
把它当成构建失败，也不执行任何清理。

本批次历史验证结果：Rust 单元测试 15 项、前端测试 5 项、TypeScript 类型检查、ESLint、
Prettier、Rust 格式检查和 Vite 构建均通过。Tauri 原生应用打包和 Windows/Linux
真机构建仍未在当前 macOS 主机上实测。

## 批次三：跨项目管理效率

状态：已实现（2026-09-15）。

### G. 搜索、筛选与排序

- 项目搜索、平台/渠道筛选、手动顺序/Git 状态/磁盘占用/名称排序。
- 收藏、基于拖拽手柄的手动排序和隐藏。
- 隐藏只影响看板，不移动或删除项目文件。

落地：项目搜索、平台/渠道筛选、名称/Git 最近提交/磁盘占用排序、收藏、手动顺序、
隐藏和本地偏好持久化已接入 Projects 看板。手动顺序通过左侧拖拽手柄实时预览，松手
后一次性提交；筛选只改变视图，不改变扫描事实。

### H. 多工作区与扫描设置

- 在 Settings 中添加、编辑和移除多个工作区。
- 配置扫描排除项，处理无效目录和重叠工作区。
- 扫描入口继续只保留在 Settings。

落地：Settings 支持多个工作区、排除目录名和工作区扫描；无效工作区以警告保留，重叠
工作区按 canonical project path 合并，Projects 页没有额外扫描按钮。

### I. 项目工具与链接

- 打开项目目录、项目终端和 Git 远程仓库。
- 打开项目声明的本地预览地址和其他链接。
- 终端由用户偏好决定，项目链接由 manifest 声明；编辑器入口暂不提供。

落地：新增 `[tools]`、`[[links]]` 结构化字段和 Rust 原生打开入口。终端不经过
shell 字符串拼接，项目声明优先，空声明回退到 Atrium 偏好或系统能力；编辑器入口
暂不提供，等待项目特定的多工具模型明确后再设计。

### J. 清理预览与结果

- 展示待清理目录、分类和空间占用。
- 支持逐项选择、逐项结果和清理后重新统计。
- 清理目标始终来自项目 manifest，不添加框架或目录名推断规则。

落地：清理条目支持逐项勾选，Rust 端将选择与 manifest 声明再次求交，执行后返回移除和
失败条目并重新统计空间；没有任何默认清理目录推断。

## 批次四：版本信息

状态：已实现（2026-09-15）；模板初始化功能已按职责边界移除。

### K. Git 版本间变更汇总

- 选择提交、分支或 Tag 范围。
- 展示提交和文件变更摘要，支持复制或导出结构化数据。
- 为后续更新日志功能提供输入，不在本批次接入 AI 或网站推送。

落地：Git 页可选择项目，输入 commit/branch/tag 等安全 revision，读取提交、文件状态、
新增/删除行统计，并复制 JSON 摘要；没有提交、Git 错误或无效 revision 时明确返回错误。

## 实施规则

- 每个批次完成后运行相关测试并生成可运行版本。
- 修改 Rust DTO、manifest 或桥接接口时同步更新 TypeScript 类型、文档和测试。
- 先保留现有用户数据和项目文件，任何删除操作都必须由用户明确触发。
- macOS 实际验证；Windows/Linux 未实测时明确标注验证边界。

## 工程质量门禁（2026-09-16）

状态：已实现。`npm run quality` 统一执行前端格式、类型、Lint、测试、构建，以及
Rust 格式、测试和严格 Clippy。`rust:check` 提供单独的 Rust 编译检查。GitHub Actions
在每次 push 和 pull request 上执行前端门禁，并在 Ubuntu、macOS、Windows 三个平台
执行 Rust 格式、测试和 Clippy 检查。该门禁验证跨平台编译边界，但不宣称当前主机已
完成三平台桌面打包。

批次三/四未完成事项：SQLite 迁移、Git/产物变化历史、更新日志生成、Website Server
同步以及 Windows/Linux 真机打包验证仍留在后续批次。项目创建和脚手架由项目自身的常规
开发工具负责，Atrium 不复制模板、不初始化 Git，也不替项目修改原生配置。
